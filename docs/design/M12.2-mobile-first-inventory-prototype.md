# M12.2 — Mobile-first adaptive workflow prototype

## Goal

Validate the M12.1 architecture against one identical operational workflow before building reusable application-wide navigation and theme infrastructure.

The selected workflow is **inventory / stock control** because it is common to field and office users, includes frequent short actions, and demonstrates the need to present the same records differently without changing business meaning.

## Prototype artifact

- QML: `src/app/ui/prototypes/InventoryAdaptivePrototype.qml`
- Standalone presentation sample with representative sample data.
- No API, database, inventory mutation, authentication, or tenant integration.
- Intended to be launched as a visual prototype in the existing Qt Quick environment; it is not yet wired into the production application shell.

## Smartphone-first experience

Primary viewport: compact phone.

1. Top app bar identifies Miselium and current workspace.
2. One-column content prioritizes stock attention and quick actions.
3. Barang masuk / barang keluar are prominent, thumb-friendly actions.
4. Search is always visible; filters remain contextual.
5. Stock records are cards with name, category, quantity, and status. Secondary actions sit on each record.
6. Bottom navigation keeps the four high-frequency destinations reachable.
7. The layout avoids dense grids and wide tables.

## Adaptive tablet and desktop experience

- **Compact (<720 logical px):** bottom navigation, single-column cards, no permanent sidebar.
- **Medium (720–1079 logical px):** compact navigation rail and two-column metrics.
- **Expanded (>=1080 logical px):** labeled sidebar, three-column metrics, desktop-width content, and secondary controls.
- The breakpoints are prototype values only. M12.3 must validate them against actual device sizes, font scaling, and orientation.

Desktop retains the same vocabulary and actions but uses persistent navigation and denser information presentation. It is not a stretched phone screen.

## Shared design language

- Industrial Professional: restrained neutral surfaces, clear borders, readable hierarchy.
- Semantic green/amber status indicators; status is also written as text and never conveyed by color alone.
- Light theme in this prototype. Light/Dark/System tokenization and persistence are M12.3 work.
- Sample data is clearly illustrative and must be replaced by tenant-scoped inventory data before production use.

## Review checklist

- [ ] A field user can identify low-stock materials without opening a detail page.
- [ ] Primary stock actions are reachable with one thumb.
- [ ] Search and item status remain readable at 360 logical px.
- [ ] Desktop users can scan quantities and statuses without excessive scrolling.
- [ ] Tablet layout remains useful in portrait and landscape.
- [ ] Font scaling and keyboard navigation are checked on real targets.
- [ ] No business rules or data mutations are implied by the visual-only prototype.

## Out of scope

- Actual inventory APIs and persistence.
- Barcode/camera scanning integration.
- Permission and role-specific action visibility.
- Final breakpoints, accessibility sign-off, and native Android visual QA.
- Production theme controller and reusable design-token implementation.

## Next step

After reviewing this paired workflow, M12.3 can implement adaptive shells and a shared theme controller without prematurely freezing component APIs.
