# M12.3 — Adaptive Application Shell & Theme Controller

**Status:** Implementation draft  
**Base:** M12.2 plus the follow-up inventory-width fix  
**Technology:** PySide6 + Qt Quick/QML; no WebView or Node.js

## Delivered

- Responsive application shell with three width bands:
  - Compact (<720 logical px): top app bar and bottom navigation.
  - Medium (720–1079 logical px): compact navigation rail.
  - Expanded (>=1080 logical px): persistent labeled sidebar and status bar.
- Shared theme controller with semantic color tokens for window, surfaces, sidebar, text, muted text, borders, accent, selection, and status.
- System / Light / Dark theme selection in the application bar.
- Theme preference persistence through Qt's `Settings` API.
- Minimum window width of 360 logical px for smartphone-sized testing.
- Existing Dashboard, Camera & Scanner, and Settings pages remain mounted in the same navigation order; no business workflow or API behavior is changed.

## Scope boundary

M12.3 establishes the shell and theme state. Existing page internals still contain page-local hard-coded dark colors. A complete migration of page controls and reusable field/data components to semantic tokens belongs to M12.4; until then, the selected theme is reflected by the shell while legacy page surfaces may retain their previous styling.

System mode follows `Qt.styleHints.colorScheme`. Platform behavior must be validated on each target OS/Qt build. If the platform does not expose a useful system color scheme, the controller falls back to Light.

## Local validation

Run `python main.py`. Check widths 390, 800, and 1280 logical px, then resize across breakpoints. Switch System / Light / Dark, restart to verify persistence, and confirm navigation remains functional.

Run `pytest -q` and `ruff check .`.

Runtime validation on Linux, Windows, and a physical Android device is not claimed by this change.
