# M12.4 — Theme Engine & Visual Customization

**Status:** Implementation ready for local verification  
**Base:** M12.3 adaptive shell and the user's pushed follow-up fixes  
**Technology:** PySide6 + Qt Quick/QML; no WebView or Node.js

## Scope delivered

### M12.4.1 — Theme Engine core
- Central `ThemeController.qml` is the single source of truth for visual tokens.
- Three independent preference axes: visual style, color palette, and appearance mode.
- Preferences persist through Qt `Settings` under the `appearance` category.
- Invalid stored palette/accent values fall back safely to Office Blue.

### M12.4.2 — Palette and semantic tokens
- Presets: Office Blue, Teal, Violet, Warm Earth, and Forest.
- Semantic tokens include window, surface, sidebar, panel, inset panel, text, muted text, border, accent, selected, status, success, warning, and danger.
- Shape tokens include card, corner, and control radius.
- Custom accent accepts validated six-digit `#RRGGBB` values.

### M12.4.3 — Visual styles and effects
- Industrial Professional is the default.
- Glassmorphism uses translucent surfaces and fine borders.
- Minimalist uses reduced corner radii.
- Industrial Dark selects a dark surface treatment.
- No mandatory blur shader is used. This intentionally avoids a costly graphics effect on mobile and devices without reliable blur support; glass surfaces use a lightweight translucent treatment instead.

### M12.4.4 — Theme settings
- Settings page provides style, palette, appearance, custom accent, and reset controls.
- Changes apply immediately to the application shell and migrated pages.
- Preferences persist locally via Qt Settings.

### M12.4.5 — Semantic-token migration
- Main application shell continues to consume the shared controller.
- Dashboard, Camera & Scanner, and Settings pages receive the same controller instance.
- Major page surfaces, text, status colors, borders, and card/control radii now reference semantic tokens.
- Camera viewfinder remains a dark preview canvas by design so camera output remains legible.

## Local verification checklist

Run `python main.py` and verify:

1. Switch between Industrial Professional, Glassmorphism, Minimalist, and Industrial Dark.
2. Switch Office Blue, Teal, Violet, Warm Earth, and Forest palettes.
3. Test System, Light, and Dark appearance modes.
4. Enable custom accent, enter valid `#RRGGBB`, and confirm invalid values do not replace the last valid color.
5. Restart the app and confirm style, palette, appearance, and custom accent persist.
6. Verify Dashboard, Camera & Scanner, Settings, navigation, and camera/scanner actions remain functional.
7. Check compact phone widths (360–430 logical px), tablet widths, and desktop widths.
8. Confirm Glassmorphism remains readable and responsive on Android; the implementation intentionally avoids mandatory blur.

Run the repository checks:

```bash
pytest -q
ruff check .
```

Runtime validation on Linux, Windows, or a physical Android device is not claimed by this change. The repository maintainer will perform that verification before merge.
